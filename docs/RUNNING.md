## 1. Просто поиграть

Ничего скачивать и устанавливать не нужно. Игра целиком живёт в двух файлах, которые
открываются любым браузером.

- **Онлайн:** https://thetoshix.github.io/nav-roguelike/ — заработает после того, как проект
  будет выложен на GitHub и включён Pages (см. [раздел 8](#8-выложить-проект-на-github)).
- **С диска:** распакуйте архив, зайдите в `dist/` и откройте `index.html` двойным щелчком.
  Если папки `dist/` нет — её создаёт сборка веб-версии, см. [раздел 6](#6-собрать-версию-для-браузера).

Сохранение хранится в самом браузере (`localStorage`), поэтому продолжить партию можно
только в том же браузере и на том же устройстве.

**Звук.** Музыка вступает только на этажах со стражами и включена по умолчанию. Ни один
браузер не даст звук до первого нажатия клавиши или щелчка — это нормально. Выключается
кнопкой **♪** в верхней панели или клавишей `M`.

## 2. Что понадобится для сборки

Собирать нужно только если хочется терминальную версию, тесты или свою веб-сборку. Для игры
в браузере — не нужно ничего.

Минимум: **компилятор с C++17** и **CMake 3.16+**. Всё остальное — по желанию.

### Windows

1. Скачайте [Build Tools for Visual Studio](https://visualstudio.microsoft.com/downloads/)
   (внизу страницы, раздел «Tools for Visual Studio») и при установке отметьте
   **«Разработка классических приложений на C++»**. Ставить всю Visual Studio не обязательно.
2. CMake обычно приезжает вместе с Build Tools. Проверить: откройте
   **«Developer Command Prompt for VS»** (найдётся в меню «Пуск») и выполните `cmake --version`.
   Если команды нет — поставьте [CMake](https://cmake.org/download/) отдельно и при установке
   выберите «Add CMake to the system PATH».
3. Git: [git-scm.com](https://git-scm.com/download/win) — понадобится в разделе 8.

Все команды ниже выполняйте в **Developer Command Prompt**, а не в обычном `cmd`: обычный не
знает, где лежит компилятор.

### macOS

```bash
xcode-select --install          # компилятор Apple Clang
brew install cmake git          # если нет Homebrew — brew.sh
```

### Linux (Debian, Ubuntu, Mint)

```bash
sudo apt update
sudo apt install build-essential cmake git
```

### Linux (Fedora)

```bash
sudo dnf install gcc-c++ cmake git
```

### Проверка

```bash
cmake --version     # должно быть 3.16 или выше
g++ --version       # или clang++ --version, или cl на Windows
```

## 3. Скачать исходники

**Вариант А — архив.** Распакуйте `nav-roguelike.zip` куда угодно. Внутри будет папка
`nav-roguelike/` — все команды ниже выполняются из неё.

**Вариант Б — из GitHub** (когда проект будет выложен):

```bash
git clone https://github.com/TheToshix/nav-roguelike.git
cd nav-roguelike
```

Что где лежит:

```
engine/          ядро: правила игры, без ввода-вывода
frontend/
  terminal/      версия для терминала
  web/           обёртка для WebAssembly, страница игры, спрайты и музыка
tests/           389 тест на GoogleTest
docs/            архитектура, тест-план, тест-кейсы, багрепорты
tools/           сборка веб-версии и генератор спрайтов
```

## 4. Собрать и запустить

Две команды. Первая настраивает сборку, вторая собирает.

### macOS и Linux

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DNAV_BUILD_TESTS=OFF
cmake --build build -j
./build/nav
```

### Windows (Developer Command Prompt)

```bat
cmake -S . -B build -DNAV_BUILD_TESTS=OFF
cmake --build build --config Release
build\Release\nav.exe
```

Сборка занимает около десяти секунд. `-DNAV_BUILD_TESTS=OFF` отключает тесты — иначе CMake
полезет в интернет за библиотекой GoogleTest. Если тесты нужны, см. [раздел 5](#5-прогнать-тесты).

### Что дальше

Откроется титульный экран: выбор героя, поле для зерна, кнопки. Управление:

| Клавиши | Действие |
|---|---|
| `hjkl` `yubn` или `wasd` `qezc` | идти; клавишу можно зажать; шаг в тварь — удар |
| стрелки, цифровой блок | то же самое, в любой схеме |
| `Shift` + направление | зажать — спринт, нажать — бег до развилки |
| `o` | дойти до ближайшего неизведанного места |
| `m` | карта всего этажа |
| `.` или `5` | переждать ход |
| `g` | подобрать |
| `i` | котомка: применить, надеть, снять |
| `d` (в WASD — `r`) | бросить вещь |
| `z` (в WASD — `f`) | колдовать |
| `>` `<` | спуститься / подняться |
| `p` | принести жертву на капище |
| `S` `R` | сохранить / загрузить |
| `T` | переключить язык |
| `?` | справка |
| `Esc` | меню: сохранить, загрузить, схема управления, язык, выход |

Схема управления переключается на титульном экране по `k`, а в партии — через меню по `Esc`,
и запоминается в `~/.nav_config` (на Windows — `nav_config.txt` рядом с игрой). В схеме WASD
буквы `d`, `z`, `q` и `s` заняты движением, поэтому сброс вещи переехал на `r`, колдовство на
`f`, а сохранение и выход живут в меню.

Начинается партия на **перекрёстке** — глубина 0. Там нет нечисти: есть капище, лестница
вниз и три вещи на постаментах. Взять можно ровно одну.

Сохранение пишется в `~/.nav_save` (на Windows — в `nav_save.txt` рядом с исполняемым файлом).
Таблица рекордов — в `~/.nav_scores` (на Windows — `nav_scores.txt` там же). Оба файла текстовые:
их можно открыть и прочитать глазами, а если удалить — игра начнёт с чистого листа.

### Партии без экрана

```bash
./build/nav --demo 20     # двадцать полных партий ботом, для проверки сборки
./build/nav --sweep 4     # четыре прогона до самого дна, для проверки контента
./build/nav --version
```

Бот сценарный: в режиме `--demo` он играет честно и доходит обычно до третьего-пятого этажа.
Это ожидаемо — он умеет уходить от взгляда Вия, но не умеет отступать и лечиться вовремя.
Строка `demo ok` в конце означает, что за все партии не сломался ни один инвариант и все
сохранения прошли круговой обход.

`--sweep` — то же самое, но герой намеренно перекачан, и вопрос другой: доходит ли игра до
конца вообще. Прогон засчитывается, только если герой добрался до 16 этажа и положил всех
восьмерых стражей; в конце должно быть `sweep ok`. Это долго — около минуты на прогон.

## 5. Прогнать тесты

Тестам нужна библиотека GoogleTest. CMake сначала ищет её в системе, а если не находит —
скачивает сам, поэтому **на первую сборку нужен интернет**.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
```

На Windows:

```bat
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build --build-config Release --output-on-failure
```

Ожидаемый результат — `100% tests passed, 0 tests failed out of 389`, около трёх секунд.

Чтобы не качать GoogleTest, можно поставить его системно:

```bash
sudo apt install libgtest-dev        # Debian/Ubuntu
brew install googletest              # macOS
```

Запустить часть тестов:

```bash
ctest --test-dir build -R Phases --output-on-failure    # только про фазы боссов
ctest --test-dir build -R Lobby --output-on-failure     # только про перекрёсток
ctest --test-dir build -N                               # показать список, ничего не запуская
```

## 6. Собрать версию для браузера

Нужен **Emscripten SDK** — компилятор C++ в WebAssembly.

```bash
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install latest
./emsdk activate latest
source ./emsdk_env.sh        # на Windows: emsdk_env.bat
cd ..
```

`source ./emsdk_env.sh` действует только в текущем окне терминала — в новом окне его нужно
повторить.

Дальше из папки проекта:

```bash
./tools/build_web.sh
python3 -m http.server -d dist 8080
```

Откройте http://localhost:8080 — это та же игра, что и онлайн.

В `dist/` окажутся ровно два файла: `index.html` (страница вместе с вшитыми спрайтами и
музыкой) и `nav.js` (движок, скомпилированный в WebAssembly и встроенный в JS). Их можно
положить на любой статический хостинг, ничего не настраивая.

**Открывать `dist/index.html` через `file://` не стоит** — браузеры не дают такой странице
загружать `nav.js`. Отсюда и локальный http-сервер в команде выше.

## 7. Перерисовать спрайты

Вся графика лежит текстом в `tools/sprites/pixels.py`: по шестнадцать строк на спрайт, точка
— прозрачность, остальные знаки — ключи в палитру.

```bash
python3 tools/sprites/build.py
```

Команда пересобирает `frontend/web/sprites.js` (то, из чего рисует браузер) и
`docs/media/sprites.png` — контактный лист со всеми спрайтами, чтобы посмотреть глазами.
Для контактного листа нужна библиотека Pillow (`pip install pillow`); без неё соберётся
только `sprites.js`, а лист будет пропущен.

Если изменить рисунок и забыть пересобрать — падает отдельная задача в CI, которая
пересобирает файл и сравнивает с закоммиченным.

## 8. Выложить проект на GitHub

Сейчас репозитория нет, поэтому ссылки на значки в README и кнопка «Играть в браузере» не
работают. Вот что нужно сделать, чтобы заработали.

### 8.1. Создать репозиторий

1. Зайдите на [github.com/new](https://github.com/new).
2. Имя: `nav-roguelike` (именно такое — на него ссылается README).
3. Публичный. **Не** ставьте галочки «Add a README», «Add .gitignore», «Choose a license» —
   всё это уже есть в проекте.
4. Нажмите **Create repository**.

### 8.2. Отправить код

Из папки проекта:

```bash
git init                       # если качали архивом, а не через git clone
git add -A
git commit -m "Навь: роглайк на C++ с терминальной и WebAssembly-сборкой"
git branch -M main
git remote add origin https://github.com/TheToshix/nav-roguelike.git
git push -u origin main
```

Если Git попросит логин и пароль — пароль не подойдёт, GitHub их больше не принимает.
Нужен **Personal Access Token**: Settings → Developer settings → Personal access tokens →
Tokens (classic) → Generate new token, права `repo`. Токен вводится вместо пароля.

### 8.3. Включить GitHub Pages

1. В репозитории: **Settings → Pages**.
2. В **Source** выберите **GitHub Actions** (не «Deploy from a branch»).
3. Готово. Workflow `pages.yml` соберёт WebAssembly и опубликует игру сам, при каждом
   пуше в `main`. Первая сборка идёт минут пять.

После этого заработает https://thetoshix.github.io/nav-roguelike/ и значки в шапке README.

### 8.4. Проверить, что CI зелёный

Вкладка **Actions** в репозитории. Там пять задач: тесты на четырёх платформах,
санитайзеры, покрытие, сборка WebAssembly и проверка, что спрайты не отстали от исходника.
Зелёные галочки на главной странице репозитория — половина впечатления от портфолио.

### 8.5. Мелочи, которые стоит поправить под себя

- В `README.md` и `README.en.md` внизу указан контакт — замените на свой, если нужно.
- В `LICENSE` стоит год и имя — проверьте.
- Описание репозитория (шестерёнка справа от «About»): короткая строка и ссылка на Pages.
  Туда же — темы: `roguelike`, `cpp`, `webassembly`, `gamedev`, `pixel-art`.

## 9. Если не собралось

**`cmake: команда не найдена`** — CMake не установлен или не в PATH. Windows: откройте
«Developer Command Prompt for VS», а не обычный `cmd`.

**`No CMAKE_CXX_COMPILER could be found`** — нет компилятора. Windows: не выбран компонент
«Разработка классических приложений на C++» при установке Build Tools. macOS: не выполнен
`xcode-select --install`.

**`CMake 3.16 or higher is required`** — старый CMake. Обновите; на Ubuntu 20.04 и старше
проще поставить с [cmake.org](https://cmake.org/download/), чем через apt.

**Сборка падает на `FetchContent` / GoogleTest** — нет интернета или он через прокси.
Соберите без тестов: добавьте `-DNAV_BUILD_TESTS=OFF` к первой команде `cmake`.

**В терминале вместо букв кракозябры** — терминал не в UTF-8. Windows: выполните `chcp 65001`
перед запуском. Ещё игра переключается на английский клавишей `T` — иногда это проще.

**Рамки и символы разъезжаются** — нужен моноширинный шрифт с поддержкой кириллицы. В
Windows Terminal подойдёт Cascadia Mono, в старом `cmd` — Consolas или Lucida Console.

**`emcmake: команда не найдена`** — не выполнен `source ./emsdk_env.sh` в этом окне
терминала. Он действует только до закрытия окна.

**Страница `dist/index.html` открывается, но игра не запускается** — открыли файл напрямую
через `file://`. Поднимите локальный сервер: `python3 -m http.server -d dist 8080`.

**Нет звука** — браузер ждёт первого нажатия клавиши или щелчка по странице. Музыка играет
только на этажах со стражами: это глубины 3, 4, 7, 8, 11, 12, 15 и 16.

**`git push` требует пароль и не принимает его** — нужен Personal Access Token, см. 8.2.
